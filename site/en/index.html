Zentrola gives Codex, Claude Code, and applications a shared model endpoint. The gateway governs credentials, access, quotas, and usage. The Marketplace brings these operations into clients and gives teams a starting point for their own workflows.

Gateway

Control requests with Keys, Groups, and logical models.

Members receive individual Virtual Keys; applications use App Keys. Clients configure a gateway endpoint and logical model code, while administrators maintain providers, credentials, and model mappings in the Web console.

Access and quotas

Grant models to members, apps, and Groups. Enforce their separate monthly Token limits at the gateway.

Model routing

Map logical models to upstream providers and credentials. Serve OpenAI and Anthropic compatible APIs with protocol conversion and failover.

Usage and costs

Inspect usage and cost details by user, app, model, provider, or credential. Export CSV and review operation logs.

Try the gatewayGET /v1/models

After starting Zentrola locally, replace the example Key with a member Virtual Key:

curl http://127.0.0.1:9527/v1/models \
  -H "Authorization: Bearer YOUR_VIRTUAL_KEY"

The endpoint returns only logical models available to that Key. Use a returned model code in client requests.

Client plugin

Use Zentrola from Codex and Claude Code.

The plugin reuses the gateway endpoint and Access Key already configured in the client. Members can check Token usage, monthly quotas, and the provider serving a model. Individually authorized Keys can also inspect reachable subscription quotas.

With management permission, a Key can use MCP to list Groups, create regular members, issue regular Keys, and enable or disable regular members. These tools cannot create administrators or grant management access to newly issued Keys.

Plugin and installation guide

Zentrola Marketplace

Clone the repository. Build your own client plugin.

The Marketplace repository includes working examples of plugin manifests, Skills, Claude Code commands, and a shared MCP server. Teams can use it as a template to connect internal tickets, project resources, or approvals, then distribute plugins through their own Marketplace.

Deployment and status

Start with a release bundle or Compose.

The backend uses Go and the Admin Web uses Vue 3. Zentrola requires PostgreSQL 17 and Redis. Windows, macOS, and Linux bundles and a Docker Compose example are available under the Apache License 2.0.
