Gateway

用 Key、Group 和逻辑模型控制请求。

成员持有独立的 Virtual Key，应用使用 App Key。客户端只需配置 Gateway 地址和逻辑模型编码； 管理员在 Web 控制台维护服务商、凭据和模型映射。

访问与配额

按成员、应用和 Group 授权模型，并分别设置月度 Token 额度；请求入口执行检查。

模型路由

逻辑模型映射到上游服务商和凭据；支持 OpenAI、Anthropic 兼容接口、协议转换及故障切换。

用量与成本

按用户、应用、模型、服务商和凭据查看调用用量与成本明细，支持 CSV 导出和操作审计。

试一次 Gateway 请求GET /v1/models

本地启动后，将示例中的 Key 换成成员的 Virtual Key：

curl http://127.0.0.1:9527/v1/models \
  -H "Authorization: Bearer YOUR_VIRTUAL_KEY"

接口只返回该 Key 有权限访问的逻辑模型，客户端使用返回的模型编码发起调用。

客户端插件

常用操作直接在 Codex 和 Claude Code 中完成。

Zentrola 插件复用客户端已有的 Gateway 地址和 Access Key。 成员可以查询 Token 用量、月度配额与当前模型的服务商； 具有单独授权的 Key 还可查询可路由订阅账号的额度。

具备管理权限的 Key 可通过 MCP 查询 Group、创建普通成员、签发普通 Key、启停普通成员。 这些工具不能创建管理员，也不会为新 Key 自动授予管理权限。

插件命令示例
Codex$zentrola:usage本月用量
Codex$zentrola:quotaToken 配额
Claude Code/usage本月用量
Claude Code/member-management普通成员管理

Zentrola Marketplace

克隆仓库，开发自己的客户端插件。

Marketplace 仓库包含插件清单、Skills、Claude Code 命令和共享 MCP 服务的实现示例。 团队可以以它为模板，对接内部工单、项目资源或审批流程，再通过自己的 Marketplace 分发插件。

  1. 01
    克隆仓库

    从现有插件结构和双客户端清单开始。

  2. 02
    实现业务工具

    编写 Skill、命令和 MCP 工具，连接团队自己的系统。

  3. 03
    注册并分发

    将插件加入 Marketplace，供成员在 Codex 或 Claude Code 中安装。

部署与现状

从发布包或 Compose 开始。

Backend 使用 Go，管理界面使用 Vue 3。运行时需要 PostgreSQL 17 和 Redis。 项目提供 Windows、macOS、Linux 发布包和 Docker Compose 示例，采用 Apache License 2.0。
