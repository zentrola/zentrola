# 首次管理员初始化

新安装的 zentrola 不再从环境变量创建默认管理员。启动后打开管理页面，`admin_user` 表为空时展示“初始化管理员”，由首次使用者设置账号、密码和确认密码。创建成功后切换为登录页面，使用刚设置的凭证登录。

这是管理账号的一次性初始化，不是开放的成员注册。业务 MEMBER 仍由管理员在成员页创建；不会把已有业务成员自动提升为管理员。

## 状态与接口

| 方法 | 路径 | 结果 |
| --- | --- | --- |
| GET | `/api/v1/auth/setup` | 无需登录，返回 `data.required`，仅说明是否需要初始化 |
| POST | `/api/v1/auth/setup` | 未初始化时创建首位管理员，请求为 `username / password`，成功返回 201、`data.initialized=true` |
| POST | `/api/v1/auth/login` | 使用设置好的账号密码登录，行为保持不变 |

初始化 POST 必须使用 `Content-Type: application/json`，不接受组织、角色等额外字段。账号为 1～64 bytes，不含控制字符或首尾空白；密码为 12～72 bytes，不含 NUL。后端使用 bcrypt 保存 Hash，不存明文。网页确认密码只用于防止输入错误，不发送给服务器。

数据库中存在任意管理员（含停用和软删除记录）时，初始化状态为关闭。直接请求 POST 返回 `409 ALREADY_INITIALIZED`；不会覆盖原密码或恢复停用账号。

物理清空 `admin_user` 后，刷新管理页面即可重新设置管理员，无需清理审计日志。初始化状态只取决于管理员表是否为空；历史认证审计保留，不参与判断。仅停用或软删除管理员不会重新开放初始化。

## 事务与启动

首次创建使用 PostgreSQL 事务级 advisory lock。获得锁后重新检查管理员表，再进行校验、Hash、账号创建和 `ADMIN_INITIALIZE` 审计写入；并发请求只允许一个成功。审计写入失败时整个事务回滚，可重新尝试，不遗留半初始化状态。审计不含密码、Hash 或 JWT。

管理员账号密码通过网页设置，不保存在 `.env` 中。启动仍需提供数据库配置、独立的 `ADMIN_JWT_SECRET`，并保留 Master Key。

忘记已有管理员密码时，使用 `zentrola password --username <账号>` 生成随机新密码；不会重新开放初始化入口。详见 [命令行与密码恢复](命令行与密码恢复.md)。

未创建管理员时服务可以启动，页面和初始化接口可访问；`/health/live` 正常，`/health/ready` 为 503、`admin=NOT_INITIALIZED`。创建管理员后 readiness 转为 READY。现有部署已有账号时直接显示登录页，不要求重新设置。

新迁移 `00005_admin_setup.sql` 增加初始化审计类型及安全历史查询索引。有新审计记录时旧类型约束会阻止 Down，不为回滚删除历史。

## 验证

- PostgreSQL 隔离测试：参数校验、内容类型、禁止客户端指定组织、审计失败回滚、12 个并发请求只有一个 201，其余 409、Hash 验证、登录和 readiness 转换、重复创建、停用、软删除及保留审计后的账号表清空。
- 浏览器测试：首次设置、确认密码、初始化后切换登录、刷新后不显示初始化、初始化状态查询失败时不开放表单、其他页面抢先完成后的 409 处理，以及原有管理页面回归。
- 独立空数据库真实启动验收：未预置管理员，浏览器设置新账号并登录成功，readiness 从 503 转为 200，重复初始化返回 409。测试密码仅保存在内存，不写入配置或报告。
- Go 全量测试（含数据库）、`go vet`、前端类型检查、生产构建和 Docker 构建通过。
- Linux 下首次初始化集成测试通过 `go test -race` 检查。
- 本地预览升级后，已有管理员登录成功，初始化状态保持关闭，页面和 readiness 均返回 200；专用验收容器与测试数据库已清理。
- 后续按用户要求调整为空表判定：保留认证审计时，物理清空管理员表后仍可初始化；隔离数据库测试覆盖重新创建、登录和历史审计保留。本地 8081 预览已验证空表返回 `required=true`，浏览器显示初始化表单。

真实首次设置验收脚本为 `web/tests/setup-live.mjs`，需显式设置 `ZENTROLA_SETUP_WEB_URL` 指向本地空库实例；它不会操作已有管理员的实例。脱敏结果保存在 `.cache/setup-live-results.json`。运行后应清理专用实例及其测试数据库。
