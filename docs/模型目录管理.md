# 模型目录管理

模型页面支持新增、编辑和启停。模型授权统一在「分组 → 模型授权」中勾选：勾选即授权，取消勾选即撤销，立即生效。列表展示所有模型，支持按名称或编码搜索；停用模型不能新增授权，已有授权仍可取消。每次操作后重新读取实际授权，失败时提示重试。新增时按官方资料填写名称和标准编码；不同服务商的调用编码由 `provider_model.upstream_model_code` 单独维护。本次不新增服务商及映射配置界面。

## 字段

| 数据库字段 | API 字段 | 规则 |
| --- | --- | --- |
| `model_code` | `code` | 官方模型编码，1～128 bytes，未删除记录唯一 |
| `display_name` | `name` | 官方模型名称，1～128 bytes |
| `input_modalities` | `inputModalities` | JSONB 非空数组 |
| `output_modalities` | `outputModalities` | JSONB 非空数组 |
| `remark` | `remark` | 备注，最多 2000 bytes，默认空字符串 |
| `status` | `status` | 新建默认 DISABLED，独立状态接口修改 |
| `created_at` / `updated_at` | `createdAt` / `updatedAt` | UTC 时间 |

输入输出类型只允许 `TEXT`、`IMAGE`、`AUDIO`、`VIDEO`。应用层和数据库同时拒绝空集合、重复值、未知枚举、null、嵌套结构。名称、编码、备注不接受首尾空白或 NUL。接口使用 JSON 数组，不接受逗号字符串或 JSON 字符串。官方信息由管理员核对，不自动调用外部目录认证。

“多模态”由输入输出类型的并集包含至少两种类型计算，不落库。输入图片不代表能够输出图片；页面分别展示两个方向。支持登记音频、视频等元数据，并不意味着网关已实现相关调用协议。

## 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/v1/models` | 分页列表，包含完整元数据 |
| GET | `/api/v1/models/{id}` | 模型详情 |
| POST | `/api/v1/models` | 创建，返回 201 |
| PUT | `/api/v1/models/{id}` | 编辑完整元数据，返回 200 |
| PATCH | `/api/v1/models/{id}/status` | 启停，沿用原接口 |

POST、PUT 请求示意（编码为占位示例）：

```json
{
  "code": "official-model-code",
  "name": "官方模型名称",
  "inputModalities": ["TEXT", "IMAGE"],
  "outputModalities": ["TEXT"],
  "remark": "用途及限制"
}
```

所有接口要求管理员认证；非法参数返回 400，编码冲突返回 409，详情或编辑的目标不存在返回 404。新增和编辑分别记录 `MODEL_CREATE`、`MODEL_UPDATE` 审计，审计失败会回滚业务写入。编辑不改变 ID、状态、分组授权、服务商映射和历史用量的 ID 关联；修改编码会改变客户端调用入口，页面显示提醒。

## 数据迁移

`00006_model_catalog.sql` 新增两个 JSONB 模态字段、备注及早期发布方字段；`00007_remove_model_publisher.sql` 移除多余的发布方字段，删除固定为 CHAT 的 `model_type`，并扩展操作日志类型约束。使用 sqlc 1.30.0 从迁移和查询源文件重新生成访问代码。

现有 Bootstrap 的 `claude-sonnet` / `claude-opus` 编码兼容保留，避免直接中断客户端。名称和状态也不会由迁移覆盖。管理员可以通过编辑显式调整为官方版本编码；本次保留初始化命令的既有别名行为。

已知初始化目录回填：Claude 系列为文本/图片输入、文本输出；DeepSeek V4 Flash/Pro 为文本输入和输出。依据 [Claude 官方模型文档](https://platform.claude.com/docs/en/about-claude/models/overview) 和 [DeepSeek 官方接口说明](https://api-docs.deepseek.com/)，核对日期为 2026-09-06；不会把独立视觉实验模型的能力赋给 Flash/Pro。

对于历史上直接写入数据库的其他模型，迁移明确报错并原子回滚，避免猜测能力。升级前需要先根据官方资料为这些记录补充迁移回填分支。输入输出字段没有默认 TEXT，新的写入必须显式提供有效集合。

前后端应一起升级。自动迁移开启时，下次启动应用执行迁移；也可按项目现有方式执行 `go run ./cmd/server migrate`。本次自动化数据库验证仅使用随机隔离 schema。
