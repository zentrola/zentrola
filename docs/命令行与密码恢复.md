# 命令行与管理员密码恢复

执行 `zentrola help` 查看自带命令，也支持 `zentrola --help`、`zentrola -h` 和 `<命令> --help`。帮助命令不会读取配置、连接数据库或启动服务。

| 命令 | 用途 |
| --- | --- |
| `zentrola start [--port <端口>]` | 后台启动 HTTP 服务 |
| `zentrola restart [--port <端口>]` | 沿用上次配置与端口重启 |
| `zentrola stop` | 优雅停止受管理的后台服务 |
| `zentrola status` | 查看后台进程、端口、配置和健康状态 |
| `zentrola start --foreground` / `zentrola serve` / `zentrola` | 前台运行，兼容容器 |
| `zentrola migrate` | 执行数据库 Schema 迁移后退出 |
| `zentrola healthcheck` | 检查服务存活状态，供容器健康检查使用 |
| `zentrola password --username <账号>` | 为指定管理员生成随机新密码 |
| `zentrola config --file <路径>` | 统一绑定已有通用配置文件 |
| `zentrola config --show` | 只显示配置路径、来源和当前环境 |
| `zentrola help [命令]` | 查看帮助 |

## 统一绑定配置

在 `bin` 目录执行一次：

```powershell
.\zentrola.exe config --file ..\.env
.\zentrola.exe config --show
.\zentrola.exe healthcheck
```

绑定保存为可执行文件旁的 `config.json`，只含配置文件的绝对路径，不复制密码。相同目录内替换二进制后绑定仍然有效；移动程序到其他目录后需重新绑定。保存前检查目标文件存在且分层配置可解析，以临时文件原子替换绑定；失败时保留旧绑定。绑定命令不连接数据库，也不执行迁移或启动服务。

配置文件选择顺序为：**单次 `--config <路径>` > 已保存绑定 > 当前工作目录 `.env`**。单次覆盖不修改绑定。绑定文件损坏、目标文件丢失或不可读取时会明确报错，不静默回退；可重新执行 `config --file` 修复。

绑定或显式 `--config` 选中的文件，其所在目录也是服务运行目录；Master Key、`web/dist` 等相对资源路径不会随启动位置改变。未绑定时保留原来的当前工作目录行为。文件中的值仍遵循 `System ENV > 环境文件 > 通用文件 > 默认值`；环境文件为通用文件路径追加 `.dev`、`.test` 或 `.prod`，不是把 `.env.dev` 当作通用文件再绑定。

`healthcheck` 优先检查由 `start` 启动的后台服务的实际端口，支持 `start --port` 覆盖后的地址；显式 `--config` 可临时指定其他配置。没有后台服务时，复用绑定读取 `HTTP_ADDR`，不依赖数据库密码、不连接数据库。请求 `/health/live` 后将接口响应体原样写入标准输出，保留 `code`、`data`、`requestId` 等字段；HTTP 200 退出码为 0，其他状态或请求失败为非 0。错误状态的响应体也会输出，诊断错误另写入标准错误。此检查只确认 HTTP 服务存活。没有后台服务、未绑定且未传 `--config` 时，保持容器原有配置读取行为：读取系统 `HTTP_ADDR`，默认 `:8080`，不加载 `.env`。

## 启动、停止和重启

```powershell
.\zentrola.exe start
.\zentrola.exe start --port 8081
.\zentrola.exe status
.\zentrola.exe restart
.\zentrola.exe restart --port 8082
.\zentrola.exe stop
```

`start` 默认后台运行，Windows 不弹出控制台窗口；启动后可关闭执行命令的终端。命令等待本实例 HTTP 服务可访问后显示 PID、访问地址和日志位置。每个可执行文件目录管理一个后台实例，重复 `start` 显示已有状态，不生成新进程。`--port` 范围为 1～65535，优先于配置中的端口，不修改 `.env` 或配置绑定。端口已占用时启动失败，并在连接数据库前退出。

`restart` 先验证待使用的配置，再优雅停止现有实例；默认保留上次运行的配置文件、环境（dev/test/prod）、工作目录和端口。配置值重新读取，其他系统环境变量使用执行命令时的值，不持久保存数据库密码等配置。`--port` 可切换端口，`--config` 可明确切换配置文件和环境；没有历史记录时按当前绑定启动。停止超时或关闭失败时不继续启动第二个实例。

程序旁的 `run/server.json` 保存进程身份、配置路径、端口和本机控制凭证；`run/server.log` 追加记录后台服务日志；`run/server.lock` 和 `run/command.lock` 使用操作系统文件锁，进程退出后锁自动释放。目录限制为当前用户访问（Windows 同时允许 SYSTEM），控制凭证不显示在命令输出中。不要在后台服务运行时删除或移动 `run` 目录。

`stop` 通过仅监听 `127.0.0.1` 的独立控制通道发送停止请求，核验随机凭证、PID、程序路径和实例标识；不会按端口查找并强制杀进程。收到停止请求后，服务停止接收请求、等待在途请求结束、关闭并排空 Usage Queue、关闭数据库，最后释放运行锁。命令等待上述过程完成；已停止时重复调用成功返回。超时会提示检查状态及日志，不自动强杀。即使配置绑定文件后来失效，`stop/status` 仍可管理已记录的后台服务。

`start --foreground` 和 `serve` 在前台运行，通过 Ctrl+C 或容器信号停止，不写后台进程记录，不受 `stop/status` 管理。不带命令继续以前台方式运行，保持现有 Docker ENTRYPOINT 和容器退出行为。旧版本或手动 `serve` 启动的进程需要在原终端停止后，才能让 `start` 使用同一端口。

进程集成测试使用隔离数据库 schema 和临时目录，验证真实后台启动、重复启动、重启继承与换端口、身份拒绝、优雅停止、端口冲突，以及 `.env` 未被改写：

```powershell
go build -o bin/zentrola.exe ./cmd/server
$env:ZENTROLA_INTEGRATION = '1'
$env:ZENTROLA_TEST_BINARY = (Resolve-Path bin/zentrola.exe).Path
go test ./cmd/server -run TestProcessLifecycleIntegration -count=1 -v
Remove-Item Env:ZENTROLA_INTEGRATION, Env:ZENTROLA_TEST_BINARY
```

## 忘记密码时

1. 在部署服务器上使用包含此功能的新版本二进制，执行 `zentrola config --show` 确认配置指向需要恢复的数据库。已有绑定时会自动复用，可用 `--config <路径>` 单次覆盖。
2. 停止使用相同 `ID_NODE` 的服务进程，避免多个进程同时使用相同节点生成审计 ID。所有服务实例均应升级到支持凭证版本校验的版本，旧版本无法执行新的 Token 撤销规则。
3. 在可信终端执行：

   ```powershell
   zentrola password --username admin
   # Windows 当前目录二进制：
   .\zentrola.exe password --username admin
   # 如果当前工作目录为项目的 bin，配置仍在项目根目录：
   .\zentrola.exe password --username admin --config ..\.env
   ```

4. 命令成功后会显示一次新密码，将其保存到密码管理器，然后启动服务并使用新密码登录。新密码为正式密码，不会强制再次修改。

`serve`、`migrate` 和 `healthcheck` 同样复用绑定，并支持在命令后传入 `--config <路径>`。若出现 `POSTGRES_PASSWORD is required`，先核对 `config --show` 和报错显示的配置路径；不要把数据库密码当作管理员登录密码。

首次升级需迁移到 `00009_admin_password_reset.sql`。启用 `MIGRATIONS_AUTO_APPLY` 时命令按现有规则自动迁移；关闭时先执行 `zentrola migrate`。密码命令不执行业务 Bootstrap，不创建账号，不加载或替换 Master Key，不启动 HTTP 服务。

`--username` 必填，只能重置已有且启用、所属组织也启用的管理员。不存在、已停用或软删除的账号会被拒绝；命令不会恢复其状态，也不接受显式密码参数。

新密码由 `crypto/rand` 生成，具有至少 128 位熵，数据库只保存 bcrypt Hash（cost 12）。密码重置、清零登录失败次数、清除临时锁定、递增凭证版本和 `ADMIN_PASSWORD_RESET` 审计在同一事务中提交，任一步骤失败均回滚。审计操作者为 `SYSTEM`，不保存密码、Hash 或 Token。

重置后仅该管理员旧 Token 失效，其他管理员和成员 Access Key 不受影响。此前没有凭证版本字段的 Token 按版本 0 处理，升级本身不强制退出，首次重置后即不再通过认证。登录与重置共用管理员行锁，即使重置恰好发生在登录提交和签发 Token 之间，旧密码登录产生的 Token 也无法通过认证。

新密码仅在事务提交成功后输出一次，不进入应用日志。终端录屏、会话记录或输出重定向仍可能保存该密码，请勿收集到共享日志。若提交结果不确定或成功后终端输出失败，重新执行命令会生成另一份新密码。

此命令依赖部署服务器和数据库访问权限，不开放无需验证身份的网页重置入口。
